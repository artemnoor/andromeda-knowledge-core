# Resumable source refresh and ontology-constrained extraction

**Date:** 2026-09-24 22:52
**Files:** ingestion pipeline, pipeline persistence/migration, AI/source/discovery adapters, evidence locators, tests and ingestion documentation
**Severity:** critical

## Problem

Source refreshes could treat `source + item + profile` as a permanent
idempotency result. After `PUBLISHED`, a later run could return the old result
without fetching the URL, so document updates were invisible. A publication
failure also discarded the successful extraction path and could be converted
into a false `SKIPPED_UNCHANGED` result on retry. The AI adapter contract did
not make the complete ontology snapshot available to a real HTTP LLM adapter.
The source boundary also lacked DNS/SSRF checks, bounded HTTP error handling,
non-static discovery and deterministic evidence locators.

## Root Cause

The stable source/item/profile identity was being used as a cache key rather
than as a stream key for multiple document attempts. No durable record stored
the last successful stage together with the fetched bytes and extraction
payload, so the system had no safe way to resume after a Core outage. The AI
port exposed metadata but did not require an `ExtractionContext` containing
ontology vocabulary. Source and evidence concerns were represented only by
minimal mock ports, leaving network and locator policy implicit.

## Solution

- Added `IngestionPipelineService`, which always re-fetches terminal attempts,
  compares document checksums, creates a new attempt for changed content and
  returns `SKIPPED_UNCHANGED` only after an actual source check.
- Persisted fetch content, extraction JSON, status, failed stage and last
  successful stage in `ingestion_pipeline_runs` with migration `0005`; the
  orchestration commits each stage before crossing the next external boundary.
- Resume logic publishes persisted extraction after a publish failure and
  resumes extraction from persisted fetched bytes after an earlier-stage
  failure.
- Added `ExtractionContext` with a detached ontology snapshot and implemented
  `StructuredJsonHttpAIAdapter`, passing object types, properties and relations
  in both the system instruction and JSON request field.
- Added DNS/private-address/credential/redirect/body-limit protection and safe
  4xx/5xx handling in `HttpSourceFetcher`.
- Added sitemap and same-origin HTML-link discovery plus deterministic HTML,
  PDF and text evidence locators.
- Added regression and persistence coverage for refresh, retry, ontology
  propagation, SSRF/HTTP failures, discovery and evidence anchoring.

## Prevention

- Treat stable source identities as stream keys; use document checksums to
  identify immutable attempts.
- Persist every successful stage before calling the next external boundary.
- Require ontology-bearing extraction contexts in production AI adapters.
- Keep network fetches behind explicit DNS, redirect, size and status guards.
- Keep regression tests for changed documents, publish outages and unchanged
  documents together so idempotency cannot regress into permanent caching.
